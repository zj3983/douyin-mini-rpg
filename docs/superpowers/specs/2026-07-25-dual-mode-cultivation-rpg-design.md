# 修仙搜打撤双模式重构设计

## 1. 文档地位

本文档是后续游戏重构的产品与技术总规格。凡是旧规格与本文冲突，以本文为准；旧规格仅保留为历史实现记录。

本次选择“双模式重构”：保留现有 Cocos Creator 3.8.8 工程、资源管线、账号接口和版本化存档基础，重做战斗核心、世界关卡与秘境副本。当前阶段先完成单机闭环，未来联网不重写战斗规则。

参考方向：

- 世界地图借鉴《英雄没有闪》的横版自动战斗、连续推进和掉落养成节奏。
- 秘境副本借鉴《病毒大逃杀》的多层房间探索、资源开门、条件事件、时间压力和撤离循环。
- 题材、美术、角色、怪物、法宝和剧情全部使用原创修仙世界观，不复制参考游戏内容。

## 2. 产品定位

- 类型：竖屏横版修仙割草与搜打撤角色扮演游戏。
- 平台：移动 Web 与抖音小游戏，单机优先。
- 视角：横版侧视，不使用俯视角。
- 战斗：没有普通攻击和手动技能按钮，角色本命术与法宝自动寻敌施法。
- 操作：世界地图以走位为主；秘境以路线选择、搜索、风险判断和撤离为主。
- 核心体验：御剑移动、法宝构筑、场景探索、专属掉落、Boss 挑战和满载撤离。

## 3. 核心循环

长期循环为：

`世界地图积累资源 -> 击败世界 Boss -> 获得副本卷 -> 探索秘境 -> 带出法宝与材料 -> 强化角色和法宝 -> 挑战更高境界与高难秘境`

### 3.1 世界地图循环

1. 角色自动向前御剑飞行，玩家点击或拖动战斗区域调整站位。
2. 本命术和已装备法宝自动锁定有效目标并施放。
3. 每关依次出现普通怪、精英事件和关底 Boss。
4. 只有击败 Boss 才能解锁下一关。
5. Boss 概率掉落副本卷，并固定产出灵石、材料和境界经验。
6. 世界地图承担日常成长、法宝组合验证和秘境入口解锁，不承担搜打撤功能。

### 3.2 秘境副本循环

1. 消耗副本卷或每日免费次数入场，每日免费次数为三次。
2. 玩家在人工设计的多层横版地图中手动移动和选择路线。
3. 怪物进入索敌范围后，本命术和法宝自动攻击。
4. 击败怪物获得开门资源、恢复物和本局临时增益。
5. 搜索炼丹房、藏宝室、阵眼、残碑等地点，获得法宝、遗物、配件和材料。
6. 时间推进会提高魔气等级，强化敌人并触发追猎 Boss 或环境变化。
7. 玩家可提前撤离，也可击败最终 Boss 后满载撤离。
8. 成功撤离才能带走主要战利品；死亡只保留绑定奖励与少量基础资源。

## 4. 世界地图设计

### 4.1 关卡结构

- 首个区域包含十关，两类精英事件和一个区域 Boss。
- 每关必须有独立的关卡节奏、怪物组合和环境变化。
- 每关背景使用完整连续图像或可无缝衔接的分层背景。
- 关卡数字、路线节点和区域名称只出现在地图选择页，不覆盖实际战斗场景。
- 不在战斗背景上叠加假树、圆环、三角形、资源点或无内容关联的几何装饰。

### 4.2 移动与镜头

- 角色默认位于屏幕左侧约 35% 的安全区域。
- 地图通过背景滚动表现向前推进，角色不得倒着走。
- 玩家可在安全战斗区内平滑调整横向和纵向位置。
- 连续点击只更新目标点，不重置坐标、速度、动画或碰撞体。
- 施法动画不产生前冲，不改变移动目标。
- 镜头不因普通命中抖动；精英击破和 Boss 破防只允许短促、低幅度反馈。

## 5. 秘境地图设计

### 5.1 地图结构

- 每个秘境包含三至五层，首个可玩秘境制作三层、约十二个房间。
- 房间类型包括普通房、精英房、藏宝室、炼丹房、机关房、隐藏房、Boss 房和撤离点。
- 地图骨架由关卡设计师制作，房间入口、事件内容、部分敌群和掉落随机变化。
- 楼梯、门、传送阵和升降机关连接楼层，不使用硬切到无关背景的方式伪造层级。
- 开门资源来自战斗和搜索，形成“打怪 -> 获得资源 -> 开门 -> 找到更高价值目标”的循环。

### 5.2 操作规则

- 点击地面设置移动目标；按住或拖动可连续调整目标。
- 靠近门、搜索点和机关后显示小型交互提示，不常驻大型摇杆和技能按钮。
- 交互期间若受到攻击，按事件规则中断或保留进度。
- 自动攻击不能阻止玩家移动、开门和撤离。
- 撤离需要短暂引导时间，受到 Boss 或精英攻击会中断，避免无风险逃脱。

### 5.3 时间压力

- 入场后魔气计时持续推进。
- 魔气阶段至少包含平静、躁动、狂暴三个档位。
- 阶段提升改变刷怪、敌人招式、环境音和可见警告，不只提高生命值。
- 狂暴阶段生成追猎 Boss 或封锁部分路线，迫使玩家撤离或决战。

## 6. 角色系统

### 6.1 境界与基础属性

- 普通等级替换为炼气、筑基、金丹、元婴、化神等境界显示。
- 角色成长只增加攻击、生命和法力等基础属性。
- 局内普通魂质升级也只自动增加攻击、生命和法力，不弹出基础数值卡片。
- 突破消耗灵石、丹药和对应境界材料。
- 基础属性不进入魂质进化选项，也不通过法宝卡片提升。

### 6.2 本命术

- 每个角色自带一个本命术，不占主动法宝槽。
- 青岚剑修使用御剑术：飞剑自动寻敌、弧线穿透、重新锁敌并返回角色身边。
- 九霄雷修使用引雷印：标记目标后从云层连续引雷，并在标记间传导。
- 本命术随角色境界成长，不通过副本掉落解锁。
- 本命术是角色识别度来源，动作、音色和攻击轨迹必须独立。

## 7. 法宝与遗物系统

### 7.1 装备规则

- 每名角色最多装备三件主动法宝和两件辅助遗物。
- 主动法宝自动索敌并造成伤害或控制。
- 辅助遗物负责触发、增幅、吸魂、护盾、恢复或资源规则。
- 同类法宝可以形成羁绊，但不能要求唯一角色才能使用。
- 性能预算不足时优先降低外围粒子，不减少法宝主体、命中判定和危险预警。

### 7.2 获得与出处

- 新法宝必须从对应秘境、Boss、隐藏事件或成就中获得。
- 每件法宝详情必须显示主要出处、可掉落难度、专属配件和当前收集进度。
- 重复法宝转化为对应碎片，用于永久强化和铭刻。
- 不允许通过升级选项凭空获得未持有法宝。

### 7.3 品质规范

- 凡品：灰白。
- 灵品：青绿。
- 玄品：蓝色。
- 史诗：紫色。
- 传说：金色。

品质颜色在背包图标、掉落光柱、详情边框、结算页和提示文本中保持一致。品质不改变法宝的核心操作逻辑，只影响基础上限、附加词条和稀有度。

### 7.4 永久强化

- 法宝永久等级消耗法宝碎片、灵石和秘境材料。
- 达到阶段上限后，需要专属配件突破。
- 铭刻改变附加属性或触发规则，与普通数值升级分离。
- 等级上限、突破条件和下一级变化必须在详情界面明确显示。
- 永久强化与角色境界、局内魂质升级互不替代。

### 7.5 局内成长与质变

- 吸收魂球提高本局魂质等级。
- 普通魂质升级按角色成长曲线自动增加攻击、生命和法力，不改变法宝永久等级，也不弹出基础属性卡片。
- 关键魂质等级弹出三选一，选项只来自当前已装备法宝的形态分支。
- 每件主动法宝每局最多质变三次。
- 质变必须改变攻击形态、轨迹、数量、范围、触发方式或目标规则，不能只是改名和加数字。
- 选项不显示角色等级、法宝升阶、攻击、生命、法力或法宝精华奖励。

御剑类法宝可形成分光、巨剑、剑阵、回旋追击、连锁穿透等分支。最终形态可以覆盖大范围战场，但必须保留玩家、怪物轮廓和 Boss 危险预警的可读性。

## 8. 怪物与 Boss

### 8.1 场景族群

- 每个世界区域和秘境拥有匹配题材的怪物池。
- 首个版本包含六种普通怪、两种精英和两个 Boss。
- 地面怪、飞行怪、远程怪和支援怪至少各有一种。
- 不同场景不能只替换背景而复用完全相同的敌群。

### 8.2 行为状态机

怪物通用状态：

`spawn -> move/select-position -> telegraph -> attack -> recovery`

并支持 `hurt`、`interrupted`、`search`、`return` 和 `death` 分支。

- 近战怪尝试包围和错位接近，不堆叠到同一坐标。
- 远程怪维持攻击距离并在被贴近后换位。
- 飞行怪保持飞行层级，使用素材自身翅膀动画。
- 精英怪拥有冲锋、范围技、召唤或封路中的至少一种能力。
- 攻击只在有效攻击帧启用命中判定，普通接触不持续扣血。

### 8.3 Boss 标准

- Boss 完整显示在安全画面内，任何动作帧不得裁掉头部、武器或肢体。
- 每个 Boss 至少有三套招式和两个阶段。
- 招式包含清晰的预警、命中和恢复阶段。
- 难度来自招式组合、空间变化和路线压力，不来自隐藏命中框或单纯血量膨胀。
- 世界 Boss 负责关卡解锁和副本卷掉落。
- 秘境 Boss 负责专属法宝、遗物和配件掉落。

## 9. 动画、美术与声音

### 9.1 序列帧资产

- 同一角色的所有动作统一打包为图集，并由清单记录帧区、顺序、帧率、循环和锚点。
- 角色至少具备待机、移动、掐诀、施法、受击和死亡动作。
- 地面怪至少具备待机、移动、攻击、受击和死亡动作。
- 飞行怪的待机、移动和攻击均必须包含素材自身翅膀变化。
- 禁止用静态图整体拉伸、摇摆、假腿、假翅膀或附加手掌代替正式动画。
- 所有角色保持原始宽高比，只允许等比缩放。
- 每帧保留透明安全边距并使用统一脚底或飞行中心锚点，避免换帧跳位。

### 9.2 法宝和命中反馈

- 每件法宝拥有独立主体图、施法动作、轨迹、命中特效和音色。
- 技能发动使用角色附近的小型名称或图标提示，不使用遮挡画面的巨大横幅。
- 命中反馈由短暂停顿、受击闪光、伤害数字、方向性碎屑、音效和可选轻震组成。
- 普通攻击效果、无意义水浪、圆环和随机几何图形不得代替具体法宝表现。
- 同类高频音效设置并发上限和冷却，避免怪物密集时叠成噪声。

### 9.3 场景与音乐

- 每个区域使用至少两至三层背景表现云雾、远景和近景视差。
- 背景图之间通过同主题过渡段、遮挡层和颜色匹配衔接，不直接硬拼。
- 环境音与场景绑定，如山风、竹雨、洞府回声、炉火和远钟。
- Boss 阶段在原场景音乐上增加节奏和低频层，不切换到无关曲风。

## 10. 经济、掉落与界面

### 10.1 货币

- 灵石：角色突破、法宝强化和基础商店。
- 仙玉：稀有货币，单机阶段由成就和高难内容获得。
- 副本卷：世界 Boss、任务和每日奖励产出。
- 抽卡卷：副本、成就和活动产出。
- 丹药与草药：恢复、突破和炼丹用途。

不新增功能重叠、无法解释用途的货币。

### 10.2 背包与装备

- 背包采用图标格子，按法宝、遗物、材料、丹药和碎片分类。
- 装备页只展示当前角色、三件主动法宝和两件辅助遗物，不兼任背包。
- 点击物品弹出详情浮层，不跳转到遮挡上下文的独立页面。
- 详情显示品质、等级、效果、出处、配件、强化需求和装备状态。

### 10.3 结算

- 世界关卡结算保持紧凑，显示关卡、Boss、奖励和继续入口。
- 秘境结算显示撤离状态、带出物、击败 Boss、探索率和撤离评价。
- 结算浮层不得遮挡关键导航，也不得在三秒后强制关闭导致玩家来不及查看。
- 奖励入账必须具备幂等标识，重复点击或回调不会重复发放。

## 11. 工程架构

### 11.1 分层原则

- 纯 TypeScript 规则层不依赖 Cocos，可在 Node 环境执行单元和模拟测试。
- Cocos 组件只负责输入适配、资源加载、节点绑定、动画和表现。
- 战斗规则通过事件输出命中、掉落、状态和结算，表现层不能反向修改权威数据。
- 世界地图与秘境使用不同会话导演，但共用角色、法宝、敌人、战斗结算和掉落模块。
- 数据表必须区分永久存档数据、局内运行数据和只读内容配置。

### 11.2 核心模块

- `WorldBattleSession`：管理世界关卡波次、精英、Boss、解锁和结算。
- `DungeonSession`：管理楼层、房间、魔气阶段、搜索、撤离和带出物。
- `PlayerMotor`：管理目标移动、安全区、楼层交互和移动锁。
- `InnateSkillRuntime`：管理角色本命术。
- `ArtifactRuntime`：管理三件主动法宝的索敌、冷却、弹道、命中和质变。
- `RelicRuntime`：管理两件辅助遗物的监听器和触发规则。
- `EnemyBrain`：执行数据驱动怪物状态机。
- `CombatResolver`：统一处理命中框、伤害、硬直、打断和死亡。
- `LootRuntime`：生成局内掉落、绑定奖励和撤离战利品。
- `ProgressionService`：处理角色境界、法宝强化、碎片和货币。
- `Presentation`：消费事件并播放动画、特效、声音、镜头和 HUD。
- `ResourceLifecycle`：按关卡加载和释放图集、背景、法宝、怪物与音频资源。
- `SaveRepository`：版本化保存玩家资料，并提供未来本地或远程实现替换点。

### 11.3 存档与未来联网

- 单机阶段使用版本化本地存档、自动保存、备份和迁移。
- 身份层、存档层、内容配置和战斗规则保持分离。
- 抖音平台身份接入后，将本地游客存档迁移到服务器账户。
- 未来联网先增加云存档、排行榜和活动，不在本阶段开发多人同步战斗。

## 12. 性能预算与降级

- 设计基准为 `750 x 1334` 竖屏，运行时保持角色和背景原始宽高比。
- 常见手机目标 60 FPS，密集战斗不得长期低于 30 FPS。
- 中端手机战斗帧时间 P95 目标不超过 20ms。
- AI 决策以 8 至 10Hz 错峰执行；移动、弹道和动画逐帧更新。
- 怪物、飞剑、法宝投射物、魂球、伤害数字和短特效全部使用对象池。
- 首版本同屏活动怪物上限通过压测确定，初始预算不超过 18。
- 三件主动法宝必须分别设定投射物、命中和特效实例上限。
- 帧时间超限时按“外围粒子 -> 碎屑 -> 次要伤害数字 -> 非关键光效”顺序降级。
- 角色轮廓、法宝主体、怪物攻击动作、Boss 危险预警和命中判定不得降级隐藏。
- 资源按区域和副本分包，首屏不加载全部角色、怪物和地图。

## 13. 首个可玩版本

第一阶段只制作一条完整纵向切片：

- 两个角色：青岚剑修、九霄雷修。
- 一个世界区域，共十关。
- 一个三层秘境，约十二个房间。
- 六件主动法宝，每件拥有三次局内质变。
- 五件辅助遗物，支持基础羁绊。
- 六种普通怪、两种精英、两个 Boss。
- 完成角色、法宝、背包、秘境选择、战斗、结算和本地存档闭环。

本阶段不做联网、排行榜、广告、付费、多人同步和大量抽卡角色。

## 14. 测试与验收

### 14.1 规则测试

- 世界关卡状态机、Boss 门槛和下一关解锁。
- 世界 Boss 副本卷掉落与奖励幂等。
- 点击移动、连续更新目标和安全区约束。
- 本命术和三件主动法宝的索敌、冷却、对象池和命中规则。
- 两件遗物的触发顺序、叠加边界和卸载清理。
- 法宝普通成长、三个质变节点和选项候选池。
- 秘境房间连通、开门资源、魔气阶段、搜索、死亡和撤离。
- 成功撤离、失败保留和带出物入账。
- 版本化存档迁移、损坏回退和重复结算。

### 14.2 资产契约测试

- 图集帧数、动作名称、帧率、循环和锚点符合清单。
- 每帧主体完整、透明边距充分且宽高比一致。
- 连续帧存在有效差异，不允许复制静态帧充数。
- 怪物素材不存在上下身分离、附加假肢体、错误朝向或死亡帧卡住。
- 法宝、遗物、材料、丹药和碎片均有可辨识图标。

### 14.3 设备与视觉测试

至少验证以下视口：

- `360 x 780`
- `390 x 844`
- `430 x 932`

每个视口必须满足：

- 顶部 HUD、角色、怪物、Boss、结算和底部导航完整显示。
- 背景与角色不拉伸、不压扁。
- 点击移动不瞬移、不抖动、不倒退。
- Boss 全部动作帧不裁切。
- 三件法宝同时发动时仍可辨认玩家、怪物和危险预警。
- 刘海屏、浏览器工具栏和系统手势区不遮挡操作。

### 14.4 试玩 Agent

试玩 Agent 需要连续完成：

1. 进入世界第一关并击败 Boss。
2. 获得副本卷并进入秘境。
3. 搜索至少三个房间，开启一扇资源门。
4. 获得一件法宝或专属配件。
5. 触发至少一次法宝质变。
6. 成功撤离并确认战利品进入背包。

报告必须覆盖：操作理解、路线决策、战斗可读性、难度曲线、法宝差异、掉落期待、帧率、卡顿、裁切和阻塞问题。

## 15. 完成定义

首个可玩版本只有在以下条件全部满足后才算完成：

- 新玩家无需长篇教程即可完成世界关卡和一次秘境撤离。
- 世界地图与秘境的操作和目标有清晰差异。
- 六件法宝在轨迹、触发、范围和质变上可明显辨认。
- 怪物具有场景匹配的动作和行为，不是统一追踪木桩。
- 连续游玩十五分钟无瞬移、贴图分离、错误朝向、UI 遮挡或结算重复。
- 自动测试、Cocos 构建、三种移动视口和试玩 Agent 均通过。
- 性能达到本文预算并保存可复核报告。

满足完成定义后，才扩展第二个秘境、更多世界区域、抽卡角色和联网能力。
