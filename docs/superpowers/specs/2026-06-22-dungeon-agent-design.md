# 副本专项 Agent 设计

## 背景

当前通用 `agent:test` 已能验证登录、主界面、各页面入口、世界地图战斗节奏、技能反馈、成长提示和基础性能。3 分钟长测显示世界地图体验稳定，但报告仍无法确认副本闭环是否真正通顺：玩家是否能进入副本、推进层数、击败 Boss 或撤离、拿到非空奖励，并在法宝页看到成长变化。

## 目标

新增一个副本专项试玩场景，用真实浏览器操作验证核心闭环：

`进入副本 -> 战斗推进 -> 触发结算 -> 获得奖励 -> 回到法宝页核对成长变化`

专项场景不替代现有通用 agent，而是通过环境变量启用，便于以后继续添加抽卡闭环、法宝升级闭环和账号存档闭环。

## 非目标

- 不在本阶段重做副本玩法、美术或数值。
- 不把所有测试都塞进通用 agent，避免一次失败难以定位。
- 不要求每次必定掉落完整法宝；允许检查碎片、精华、材料、券、灵石或法宝进度变化。

## 使用方式

新增环境变量：

```bash
GAME_AGENT_SCENARIO=dungeon npm run agent:test
```

默认不传时继续运行当前通用体验测试。

## 测试流程

副本专项 agent 启动后执行：

1. 进入游客档案并关闭登录面板。
2. 记录进入前的关键状态：副本卷、抽卡券、灵石、法宝精华、材料、法宝页已获数量、法宝技能进度。
3. 打开副本页，选择第一个可进入副本。
4. 进入战斗页后持续推进，自动选择魂质进化卡，等待以下任一结果：
   - 副本结算页出现。
   - 副本状态显示撤离门或下一层门已找到。
   - 达到超时时间。
5. 如果出现门按钮，点击进入下一层或撤离，继续等待结算。
6. 结算后记录奖励文本，并关闭结算。
7. 打开法宝页，再次记录法宝相关状态。
8. 生成专项报告，标记闭环是否通过。

## 成功标准

副本专项报告通过需要满足：

- 副本入口可见且可点击。
- 副本模式成功进入。
- 战斗期间击杀数、层数、门状态或 Boss 状态至少一种发生变化。
- 出现结算页，或明确报告未结算原因。
- 结算奖励不是空白。
- 结算后至少一种成长资源发生变化：副本卷、抽卡券、灵石、法宝精华、材料、法宝进度或已获法宝数量。

如果战斗流程无法结算，但数值状态可证明推进过，报告应失败并归因为“副本闭环未完成”，而不是普通页面失败。

## 数据采样

新增专项采样函数收集：

- `mode`：当前是否为副本模式。
- `kills`：击杀数。
- `wave`：层数或关卡文本。
- `quest`：副本目标文本。
- `message`：状态提示。
- `tickets`：抽卡券。
- `stones`：灵石。
- `artifactSummary`：法宝页标题和已获数量。
- `artifactProgress`：本命术三条技能进度文本。
- `settlementText`：结算面板奖励文本。

这些字段只用于报告和判断，不改变游戏状态。

## 失败归因

专项报告需要把失败分为几类：

- `entry`：无法进入副本。
- `combat`：进入后没有击杀、层数、Boss 或门状态变化。
- `settlement`：推进过但没有结算或撤离。
- `reward`：结算存在但奖励为空或资源没有变化。
- `artifact`：奖励变化存在，但法宝页没有可见进度变化。
- `runtime`：页面错误、请求错误、画面空白或比例异常。

## 测试与验证

需要新增或更新测试：

- `game-agent-core` 纯函数测试：副本闭环报告能区分通过、未结算、空奖励、法宝未变化。
- agent 运行验证：`GAME_AGENT_SCENARIO=dungeon GAME_AGENT_PLAYTEST_MS=180000 npm run agent:test`。
- 现有默认 `npm run agent:test` 仍保持通用体验流程。

## 风险

- 当前副本难度或结算条件可能导致专项 agent 第一次失败。失败本身是有效信号，后续再按报告修数值或引导。
- 副本奖励有随机性，判断不能只依赖“新法宝解锁”，要允许碎片、材料、精华、灵石等任一成长变化。
- 如果结算页自动关闭太快，agent 需要在战斗过程中高频轮询结算面板，避免错过奖励文本。
