# Boss 古篆符胆预警设计

## 目标

将第一关 Boss 当前的半透明实心矩形预警替换为修仙题材的“古篆符胆”表现，同时保持已有战斗判定、预警时长、攻击时序和对象池上限不变。

完成后的预警必须满足：

- 玩家能在 0.8 秒内看懂危险区域和闪避方向。
- 阵纹保持通透，不遮挡角色、怪物和飞剑。
- 三种 Boss 招式具有不同符胆与运动方式，不再共用同一种矩形表现。
- 预警图形严格服从权威判定区域，视觉不能比伤害范围更小。
- 移动端运行时复用对象池，不按帧创建节点、材质或贴图。

## 选定方向

采用“B2 古篆符胆”的混合渲染方案：

- `Graphics` 绘制可伸缩的阵框、刻线、节点和倒计时边。
- 三张透明 PNG 提供每种招式的古篆符胆核心。
- 已有冲击贴图与少量程序粒子表现技能爆发。
- 碰撞判定仍只读取 `BossBrain` 发出的 `area`，视觉层不得反向修改战斗数据。

不采用整张 PNG 拉伸，因为它会随判定区域变形；不采用全程序绘制，因为单靠几何线条难以达到古篆符胆的题材辨识度。

## 招式表现

### 竹海横扫

- 符胆：`斩`。
- 预警：阵框从 Boss 一侧向攻击方向展开，中央符胆由暗到亮。
- 倒计时：外框四边按剩余时间依次点亮，最后 0.15 秒加快闪烁。
- 闪避信息：危险区上下边界清楚，边界外不增加装饰，保留上下逃生空间。
- 爆发：阵框瞬间转为白金，沿横向掠过一道短寿命剑气碎光，然后立即淡出。

### 地脉竹刺

- 符胆：`突`。
- 预警：三个落点各自显示小型符胆，严格按 BossBrain 的 marker 顺序出现。
- 倒计时：符胆下方的地脉裂纹从中心向外生长，不能超出对应判定矩形。
- 爆发：朱砂符胆向内收缩，地面出现青白竹刺闪光；三个落点分别激活，不合并成一个大框。

### 山岳咆哮

- 符胆：`镇`。
- 预警：危险扇区按波次点亮阵纹，中央符胆保持稳定。
- 安全缺口：完全不绘制危险填色与符胆，只用两条青白边线标出缺口边缘。
- 爆发：每一波由内向外扩散白金刻线，上一波快速衰减，避免多层实心色叠满屏幕。

## 视觉规范

- 预警主色：暗金 `#E8BE58`、朱砂 `#A43A2C`。
- 灵力辅色：青白 `#8DE8DA`，只用于安全边界和少量节点。
- 爆发高光：白金 `#FFF0BD`。
- 危险区内部透明度保持低于 20%，不使用当前大面积实心填充。
- 符胆是唯一可读单字，不显示招式名、教程文字或额外提示标签。
- 所有线条按屏幕像素下限钳制，竖屏缩放后仍保持至少 2 像素可见宽度。

## 组件边界

### `BossTelegraphVisualProfile`

新增纯数据映射，将 `danger.kind` 解析为符胆资源、颜色、边框样式和爆发样式。该模块不依赖 Cocos 节点，便于单元测试。

### `BossTelegraphPresenter`

继续负责预警分组、时序、对象池与代际清理；绘制入口从通用 `drawArea` 拆为：

- `drawSweepTelegraph`
- `drawSpikeTelegraph`
- `drawRoarTelegraph`
- `drawImpact`

Presenter 根据 profile 绘制阵框，并将符胆 Sprite 绑定到池化节点。它不计算伤害，也不改变激活时间。

### 池化节点

Boss 特效节点增加一个 `Sprite` 子节点作为符胆层，保留 `Graphics` 作为阵框层。节点回收到池时必须清除图形、贴图、透明度、缩放和旋转，防止不同招式之间串状态。

## 资源

新增三张透明背景 PNG：

- `Assets/Skills/BossDomain/talisman_sweep.png`
- `Assets/Skills/BossDomain/talisman_spike.png`
- `Assets/Skills/BossDomain/talisman_roar.png`

每张图只包含单个古篆符胆与少量残缺朱砂纹理，不包含阵框、背景、发光或说明文字。运行时发光由节点颜色与透明度完成，避免为不同亮度重复贴图。

## 数据流

1. `BossBrain` 生成带 `danger.kind` 和权威 `area` 的预警命令。
2. `EnemyCombatResolverAdapter` 保持现有时序校验并交付不可变预警数据。
3. `BattleRuntimeController` 将 Boss 预警交给 `BossTelegraphPresenter`。
4. Presenter 查找视觉 profile，从对象池取得节点，按 `area` 设置位置和尺寸。
5. 到达权威激活时间后，同一分组的预警节点切换为爆发表现并按现有 duration 回收。
6. Boss 中断、死亡、关卡重建或代际变化时，Presenter 清理所有预警和爆发节点。

## 性能约束

- 保持 `BOSS_HAZARD_POOL_CAPACITY` 和现有峰值并发测试。
- `update` 中只更新已激活节点的透明度、颜色和刻线进度。
- 不在 `update` 中加载资源、创建数组纹理、创建节点或注册事件。
- 符胆资源在第一关加载时预取；加载失败时回退为无字符阵，不影响战斗判定与攻击激活。
- 同屏高峰仍需覆盖山岳咆哮三波与竹刺并发，不允许因表现升级丢失任何权威预警。

## 测试与验收

- 单元测试覆盖三种 `danger.kind` 到视觉 profile 的稳定映射。
- Presenter 测试继续验证预警数量、判定区域、激活时序、代际清理和对象池容量。
- 新增池化复用测试，连续切换横扫、竹刺、咆哮后不存在残留符胆或图形状态。
- 构建产物验证必须通过，并确认三个符胆资源进入 Web 包。
- 在 390×844 和横屏尺寸各自动试玩到 Boss 阶段，控制台零错误。
- 目视确认人物、Boss、飞剑在预警期间仍清晰可见，安全缺口与真实无伤区域一致。

## 非目标

- 本轮不修改 BossBrain 攻击选择、伤害、范围或预警时间。
- 本轮不增加新的 Boss 招式。
- 本轮不重做普通怪物的预警表现。
- 本轮不调整关卡数值、奖励或结算流程。
