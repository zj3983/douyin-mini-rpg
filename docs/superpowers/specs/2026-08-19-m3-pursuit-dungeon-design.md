# M3 雾竹秘境追猎副本设计

## 1. 目标与范围

M3 将现有副本房间按钮原型升级为首个可完整游玩的搜打撤秘境。首个秘境为“雾竹秘境”，使用三层、十二个手工房间，以持续增长的魔气和跨房追猎 Boss 作为核心压力。

本规格服从 `2026-07-25-dual-mode-cultivation-rpg-design.md`。本阶段只完成一个正式秘境、一个追猎 Boss、对应专属资产和完整存档闭环，不扩展第二秘境、不做联网、不重做角色系统，也不把世界地图功能混入副本。

### 1.1 玩家体验目标

- 单局目标时长为 6 至 9 分钟。
- 玩家需要在搜索收益、开门消耗、魔气压力和撤离时机之间做判断。
- 前两层的 Boss 只能击退，第三层满足条件后可正式击杀。
- 玩家既可提前撤离，也可冒险击杀 Boss、开启秘藏后满载撤离。
- 世界地图与秘境在操作目标、空间结构和风险节奏上有明确区别。

## 2. 核心流程

`消耗青竹令或免费次数 -> 探索半迷雾房间 -> 战斗与搜索获得开门资源 -> 魔气升级 -> 击退追猎 Boss -> 选择早撤或深入 -> 解锁最终 Boss -> 获取法宝或配件 -> 引导撤离 -> 战利品入账`

入场后采用混合魔气推进：角色移动和战斗时按真实时间增长，搜索和强开高价值门额外增加魔气；暂停、法宝选择和结算时停止计时。

## 3. 三层十二房间

地图骨架固定，每局由 `seed` 决定部分敌群、房间事件和掉落。进入楼层时显示房间连通关系，但相邻房间只显示风险轮廓；玩家进入房间后才永久揭露其真实类型和内容。

### 3.1 第一层：雾竹外径

1. 入口：建立副本目标、魔气和半迷雾地图。
2. 林径战斗：产出第一批开门资源。
3. 废弃丹房：提供恢复物和凝露草，搜索会推进魔气。
4. 封印藏室：消耗资源开启，提供高价值材料或局内增益。

本层结束前触发第一次追猎。Boss 以护盾状态出现，玩家破盾后将其击退，Boss 不损失最终生命。

### 3.2 第二层：青灯竹桥

5. 竹桥兽群：更密集的场景匹配敌群。
6. 迷雾剑阵：机关房，提供路线或战斗优势。
7. 守门精英：稳定产出进入深层所需资源。
8. 残损撤离阵：允许玩家提前撤离，但奖励等级低于最终撤离。

本层触发第二次追猎。Boss 封锁一条可选路线；玩家需要存活到破绽出现或再次破盾。系统必须保证封路后仍存在一条可达撤离路径。

### 3.3 第三层：竹皇洞天

9. 洞天前殿：最终补给和路线选择。
10. 竹皇祭坛：激活后解除追猎 Boss 的不死护盾。
11. 秘藏剑冢：仅在最终 Boss 被击败后开启，产出青霜御剑匣或专属配件。
12. 完整撤离门：玩家可在修复后直接离开，也可击败 Boss、开启剑冢后返回撤离。

多数同层道路允许双向返回。狂暴封路和明确标识的楼层机关可以改变路线，但不得制造无解死路。

## 4. 魔气与追猎 Boss

### 4.1 魔气阶段

| 阶段 | 有效时间 | 行为变化 |
| --- | --- | --- |
| 平静 | 0 至 120 秒 | 普通敌群，搜索风险较低 |
| 躁动 | 120 至 240 秒 | 精英招式增强，Boss 开始跨房追猎 |
| 狂暴 | 240 秒后 | 追猎间隔缩短，环境警告增强，部分回头路线封锁 |

- 搜索普通地点额外推进 12 秒。
- 搜索高价值藏室或强开资源门额外推进 20 秒。
- 只有有效游戏时间计入魔气；暂停、地图全屏查看、法宝选择和结算不计时。
- 单帧时间增量必须设上限，掉帧后不得一次跨过多个阶段、Boss 攻击或撤离引导。

### 4.2 Boss 状态

追猎 Boss 依次经历：

`未出现 -> 第一次追猎 -> 被击退 -> 第二次追猎并封路 -> 被击退 -> 真身待解锁 -> 最终 Boss 战 -> 击败`

- 前两次追猎只结算护盾，不能击杀 Boss，也不扣除最终生命。
- 第三层激活竹皇祭坛后，Boss 才切换为具有完整生命和阶段招式的真身。
- 玩家不激活祭坛也可修复完整撤离门离开。
- Boss 追猎前依次表现竹叶逆流、灯火熄灭、低频音效和屏幕边缘雾气，之后短暂显示“竹皇将至”。
- 只有最终 Boss 战显示完整 Boss 血条和阶段预警。

## 5. 规则架构

采用纯 TypeScript 权威规则层加 Cocos 表现层，不把副本规则直接堆入现有战斗启动组件。

### 5.1 核心模块

- `DungeonSession`：持有运行 ID、seed、当前房间、携带物和子模块快照，作为副本会话入口。
- `DungeonMapRuntime`：管理十二房间、半迷雾揭露、双向路线、资源门、封路和楼层切换。
- `DungeonPressureRuntime`：管理有效时间、搜索惩罚和三档魔气。
- `DungeonEncounterDirector`：根据房间配置生成普通怪、精英和事件，复用现有怪物 AI、战斗结算和对象池。
- `PursuitBossRuntime`：管理两次击退、封路、真身解锁和最终击败。
- `DungeonLootRuntime`：区分绑定奖励、局内携带物和撤离后永久奖励。
- `DungeonExtractionRuntime`：管理撤离引导、中断、完成和幂等结算。
- `DungeonRunPresenter`：消费规则快照和事件，负责场景、动画、音频、HUD 与结算，不反向修改规则。

### 5.2 事件与确定性

规则层输出明确事件，包括：

- `pressure-phase-changed`
- `room-revealed`
- `pursuer-entered`
- `pursuer-repelled`
- `route-sealed`
- `loot-carried`
- `extraction-started`
- `extraction-interrupted`
- `extraction-completed`

相同配置、输入序列和 `seed` 必须产生相同结果。动画失败、丢帧或音效加载失败不得改变规则结果。

## 6. 操作与表现

- 秘境使用独立战斗页面，运行期间隐藏世界地图底部导航和仓库类功能区。
- 玩家点击或拖动地面移动，本命术与法宝自动索敌。
- 角色靠近门、搜索点、祭坛或撤离阵时才显示小型交互提示，不保留大型摇杆和技能按钮。
- 每层拥有独立完整背景和前景遮罩：雾竹外径为青绿湿雾，青灯竹桥为冷蓝灯火，竹皇洞天为金青祭坛。
- 房间通过前景、光照、破损程度和交互物区分；不在战斗背景叠加圆圈、假树、关卡编号或无关几何装饰。
- 顶部仅保留角色生命、当前楼层、魔气条和携带战利品数量。
- 半迷雾地图通过地图图标打开；打开时暂停规则计时，不常驻遮挡角色。
- 战利品在场景内掉落并自动吸取。高价值物品短暂展示图标、品质和名称，不强制打开详情页。
- 撤离要求角色在阵内持续引导 3 秒；受到精英或 Boss 的有效伤害会中断，并显示中断原因。
- 结算浮层高度不超过可用屏幕约 70%，展示撤离状态、探索率、Boss 状态和带出物，可手动关闭，不自动消失。

## 7. 奖励与失败

- 残损撤离阵允许早撤，但其结算评价和高价值奖励低于完整撤离。
- 只有击败最终 Boss 才能开启秘藏剑冢。
- 成功撤离后，携带物通过运行 ID 幂等写入永久存档。
- 死亡、主动放弃和追猎失败不写入高价值携带物，只保留明确标记的绑定奖励。
- 重复点击、重复回调和重开后的重复提交不得二次发奖。

## 8. 入场、保存与恢复

入场采用以下事务顺序：

1. 加载并验证副本配置及关键资源。
2. 创建带 seed 的运行快照。
3. 扣除青竹令或每日免费次数。
4. 保存入场状态并进入副本。

配置损坏、关键资源加载失败或会话创建失败时不得扣除入场消耗。

系统在进入房间、获得高价值物品、魔气换阶段和开始撤离时保存局内快照。应用切后台或重开后恢复同一 seed 和状态。快照损坏时结束该局、退还本次入场消耗，但不发放携带物。

## 9. 测试与验收

### 9.1 规则测试

- 十二房间全部可从入口到达，并存在有效撤离路径。
- 半迷雾揭露、资源门扣除、楼层切换和封路符合配置。
- 封路后不得出现无解死路。
- 魔气在三档间准确切换，暂停状态不推进。
- Boss 只能在前两次被击退，并在祭坛激活后才能被击杀。
- 成功撤离、失败保留、断点恢复和奖励幂等正确。

### 9.2 模拟与集成测试

- 相同 seed 与输入重放结果一致。
- 自动批量运行至少 100 局，不出现死路、负资源、重复奖励或无法结束。
- 覆盖进入、切层、搜索、追猎、早撤、最终击杀、满载撤离、死亡和断点恢复。
- 试玩 Agent 必须完成搜索三间房、开启资源门、经历追猎、获得法宝或配件并成功撤离。
- 试玩 Agent 另跑一次提前撤离和一次死亡流程。

### 9.3 画面与性能

- 在 `750 x 1334`、常见安卓长屏和桌面预览下，角色、Boss、HUD、交互提示和结算完整显示。
- 同屏最多 18 个活动怪、追猎 Boss 与三件法宝同时运行。
- 中端设备目标帧时间 P95 不超过 20ms，技能释放时不得持续低于 30 FPS。
- 连续游玩一局不得出现角色瞬移、贴图分离、错误朝向、Boss 裁切、UI 遮挡或结算重复。

## 10. 完成定义

M3 只有在以下条件全部满足后才算完成：

- 玩家能从副本入口连续完成一次提前撤离和一次击杀 Boss 后的满载撤离。
- 三层在背景、房间内容、怪物组合和风险节奏上可明确辨认。
- 魔气与追猎形成可感知的决策压力，而不只是数值增长。
- 断点恢复、死亡损失、撤离入账和重复结算均通过自动测试。
- Cocos 构建、三类视口、性能验证和试玩 Agent 报告全部通过。
