# 正式登录界面设计

## 目标

把当前账号弹窗改成正式手游入口。玩家第一次打开游戏时应看到修仙题材明确、反馈清楚、层级干净的登录页，而不是账号、存档、角色创建、账号中心混在一起的功能面板。

## 已确认方向

采用 A 方案：正式启动页。

- 主视觉为修仙登录封面：云海山门、真人感剑修、脚踩飞剑、灵光，不使用抽象 SVG、飞机状椭圆、科幻元素或像素风。
- 背景云层需要动：用多层云雾贴图或渐变雾层做低速横向/纵深视差移动。
- 人物衣服需要飘动：人物不做整体抖动，使用角色层轻微呼吸位移，并为袖口、衣摆、剑光增加低幅度帧循环或遮罩光效。
- 标题、服务器状态、登录表单由前端 UI 叠加，不写死在图片里。

## 页面结构

登录页仍复用现有 `#profile-panel` 入口和账号逻辑，但视觉上拆成三个区域：

1. 启动页主视觉
   - 全屏竖版背景。
   - 顶部显示服务器状态和公告入口。
   - 左上或上半区显示游戏名 `虚境试炼` 与短副标题。
   - 角色和飞剑主视觉放在中右区域，避开底部表单。

2. 账号登录区
   - 底部固定登录面板，包含账号、密码、登录进入。
   - 登录 / 注册仍是两个明确状态，但不再像调试标签。
   - 游客试玩为次级入口，并标明本机试玩、不云同步。
   - 最近角色单独显示为继续入口，不抢主按钮层级。
   - 登录、注册、游客进入都有忙碌态和错误反馈。

3. 登录后的账号中心
   - 登录后再显示账号中心，不与未登录页混排。
   - 保留现有角色档案、云端同步、账号安全功能。
   - 角色创建仍在登录后触发，避免首次登录页过载。

## 动画设计

动画只服务沉浸感，不影响操作。

- 云层：2 到 3 层不同透明度的雾气缓慢平移，循环周期 24 到 50 秒。
- 角色：主体轻微上下浮动，幅度不超过 4px，周期约 4 到 6 秒。
- 衣摆/袖口：使用 2 到 3 个轻微差异帧或光影遮罩循环，周期约 1.8 到 2.8 秒。
- 飞剑：剑身发光和尾迹轻微流动，不出现飞机、飞船、椭圆机翼感。
- 性能保护：移动端优先使用 transform/opacity，不使用大面积 blur 动画；低性能时减少云层数量。

## 数据和状态

现有账号数据模型保持不变：

- 登录模式：`login` / `register`。
- 游客模式保留，但弱化为试玩入口。
- 最近档案、角色栏位、云同步、密码修改逻辑继续复用。
- DOM 兼容性保留，避免破坏现有自动测试和游戏 agent：
  - `#profile-panel`
  - `#profile-entry-status`
  - `#profile-guest`
  - `#profile-submit`
  - `#profile-create-confirm`
  - `#profile-btn`
  - `#profile-center-tabs`

## 资产计划

实现时生成或接入这些项目内资产：

- `public/assets/login/login-bg-xianxia.png`：无文字的修仙云海山门背景。
- `public/assets/login/login-cloud-*.png`：可循环移动的云雾层。
- `public/assets/login/login-cultivator-frame-*.png`：剑修角色帧，表现衣摆和袖口轻微飘动。

若角色透明边缘不理想，优先改为背景融合式角色帧，不强行做复杂透明抠图。

## 样式原则

- 正式、清爽、可玩，不做营销落地页。
- 修仙题材信号要强：山门、云海、飞剑、衣袍、灵光。
- 登录按钮、输入框、反馈信息要像正式游戏入口，而不是后台表单。
- 手机竖屏优先，桌面浏览时保持居中手机画幅。
- 不使用单调深蓝一色，加入玉青、白金、淡金作为层次。

## 测试和验收

完成后至少验证：

- `npm test`
- `npm run build -- --base=/game/douyin-mini-rpg/`
- `npm run agent:test`
- 浏览器检查登录页：
  - 未登录时显示正式启动页。
  - 登录、注册、游客试玩都有反馈。
  - 最近角色不遮挡表单。
  - 登录后账号中心正常打开。
  - 云层在动，人物衣袍有轻微飘动。
  - 页面没有飞机感、科幻感、抽象几何感。
